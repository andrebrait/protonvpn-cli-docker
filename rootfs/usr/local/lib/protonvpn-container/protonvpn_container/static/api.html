Use the API

One API for the WebUI and scripts. Download OpenAPI 3.1 JSON.

Generate a random key, set it as the container's API_KEY environment variable, and restart the container. Keep it separate from WEBUI_PASSWORD. Never put secrets in URLs. Use HTTPS outside a trusted local network.

openssl rand -hex 32

Without OpenSSL:

docker run --rm python:3-alpine python -c "import secrets; print(secrets.token_urlsafe(32))"

For the examples below, export API_KEY in your terminal to the generated key. Replace credential and code placeholders before running sign-in examples.

An empty API_KEY disables bearer authentication. It does not close an open WebUI: when WEBUI_PASSWORD is empty, anyone who can reach this port can control the VPN. With a password set, use a valid session cookie or bearer key.

Every POST needs a JSON object. Cookie and open-mode writes also need X-Requested-With: protonvpn-webui; only a valid bearer key skips that header. Errors use {"error": "message"} with a non-success HTTP status. No key or password is shown here.

Password-only cookie flow

With WEBUI_PASSWORD set and API_KEY empty, no bearer key is needed. Replace your-webui-password in the login JSON below. Run these commands in the same directory: log in, read status, request disconnect, then log out. Every protected endpoint also has a cookie example below.

Keep cookies.txt private: it grants access until logout or session expiry. The commands set restrictive file permissions. Cookie writes require both the JSON body and X-Requested-With header.
